## 1. ملف `.env` — ماذا يحتوي ومن يملك الوصول

### المتغيرات المطلوبة

| المتغير         | الوصف                                    | مثال                                        |
|-----------------|------------------------------------------|---------------------------------------------|
| `ODOO_URL`      | رابط خادم Odoo                           | `https://odooprosys-hr19.odoo.com/`         |
| `ODOO_DB`       | اسم قاعدة البيانات                       | `odooprosys-hr19-main-37916265`             |
| `ODOO_USERNAME` | اسم المستخدم لحساب التكامل              | `khaled`                                    |
| `ODOO_API_KEY`  | مفتاح API (يُعامَل كسر)                  | *(لا يُعرض هنا — موجود فقط في `.env`)*       |

### قواعد الوصول

1. **`.env` على جهاز واحد فقط** — جهاز صاحب المشروع (خالد). لا يُنسخ ولا يُرسل لأي شخص أو أداة.
2. **`.env` مُستثنى من Git** — مسجّل في `.gitignore` ولا يُرفع للمستودع أبداً.
3. **لا يُشارك المفتاح مع أي أداة ذكاء اصطناعي** — كما هو مُقرَّر في `project_briefing.md` (بند 4).
4. **لا يُلصق المفتاح في أي ملف كود أو ملف توثيق** — يُقرأ فقط من متغيرات البيئة عبر `os.environ`.

### التحقق الآلي الموجود

- `odoo_write_gateway.py` يقرأ المتغيرات من `os.environ` فقط (لا hardcoded).
- `environment_policy.py` يمنع أي كتابة لقاعدة بيانات غير مُدرجة في `ALLOWED_TEST_DBS`.
- `.gitignore` يستثني `.env` و`.env.*` وجميع الملفات الحساسة.

## 2. تدوير مفتاح API — متى ولماذا وكيف

### متى يجب التدوير

| الحدث                                                | الإجراء                                |
|------------------------------------------------------|----------------------------------------|
| انتهاء فترة تجارب مكثفة (مثل الآن)                  | دوّر المفتاح الحالي                    |
| قبل الانتقال لاستخدام حقيقي (Pilot أو إنتاج)        | أنشئ مفتاحاً جديداً واحذف القديم       |
| اشتباه في تسريب المفتاح (لُصق في مكان عام، إلخ)    | دوّر فوراً                             |
| تغيير الجهاز الذي يُدار منه المشروع                  | أنشئ مفتاحاً جديداً على الجهاز الجديد |

### خطوات التدوير اليدوي

1. **ادخل إلى Odoo** بحساب `khaled` عبر المتصفح:
   `https://odooprosys-hr19.odoo.com/web#action=base.action_res_users`

2. **افتح ملف المستخدم** → تبويب "Account Security" أو "Preferences" → "API Keys".

3. **أنشئ مفتاحاً جديداً**:
   - اضغط "New API Key"
   - سمِّه باسم واضح (مثل `hr-agents-automation-oct2026`)
   - انسخ المفتاح المُولَّد فوراً (يظهر مرة واحدة فقط)

4. **حدّث `.env`** على جهازك:
   ```
   ODOO_API_KEY=<المفتاح الجديد>
   ```

5. **تحقق أن المفتاح الجديد يعمل**:
   ```bash
   python scripts/rotate_api_key.py --verify
   ```
   هذا يقرأ `.env` الحالي ويختبر الاتصال بـ Odoo (قراءة فقط).

6. **احذف المفتاح القديم** من واجهة Odoo (مهم — لا تتركه فعّالاً).

7. **تأكد** أن كل السكربتات تعمل:
   ```bash
   python -m pytest tests/ -v
   ```

### سكربت المساعدة

```bash
# التحقق من صلاحية المفتاح الحالي (لا يغيّر شيئاً)
python scripts/rotate_api_key.py --verify

# عرض معلومات الاتصال الحالية (بدون المفتاح نفسه)
python scripts/rotate_api_key.py --info
```

## 5. ملفات حساسة إضافية يجب حمايتها

| الملف/المجلد | الحساسية | الحماية |
|---------------|----------|---------|
| `.env`, `.env.*` | مفاتيح API | `.gitignore` |
| `output/` | بيانات موظفين (أسماء، بريد، جوال) | `.gitignore` |
| `output_catalog/` | قد يحتوي بيانات مرجعية | `.gitignore` (يجب إضافته) |
| `logs/` | سجلات قد تحتوي بيانات حساسة | `.gitignore` (يجب إضافته) |
| `approval.json` | يحتوي معلومات الموافقة | لا يحتاج حماية خاصة (لا بيانات شخصية) |
| `*.jsonl` (نتائج writer) | بيانات موظفين حقيقيين | تُحفظ في `output/` المحمي |
