# إصلاحات مركز عمليات Odoo HR

هذه التغييرات تصلح الربط بين المحادثة والعمليات والسجل، وتعيد تصميم الفقاعات وشريط الكتابة دون نقل الواجهة إلى إطار جديد. لا تتضمن تنفيذ كتابة على قاعدة Odoo حية أو تعديل مفاتيح اتصال المستخدم.

## الإصلاحات

- **السجلات:** تضم قائمة التدقيق عمليات الوكلاء، وتعرض 10 سجلات افتراضياً مع السابق والتالي وأرقام الصفحات واختيار حجم الصفحة. الحدود غير الصحيحة يعيد API رفضها، وفشل التحميل يظهر رسالة وإعادة محاولة بدلاً من الانتظار الدائم.
- **البحث:** إصلاح استدعاء `list_operations` غير الموجود. البحث يشمل العمليات الأقدم من 50 عملية، ويدعم معرف العملية ومعرف الخطة والبادئة القديمة `OP-AGENTS-`.
- **ملف السجل:** النافذة تعرض بيانات العملية والخط الزمني والمحادثة المحفوظة فعلياً. لا تُختلق محادثة للعمليات القديمة التي لم تحفظ نصوصها.
- **متابعة العمليات:** لكل طلب جديد معرف محادثة مستقل. فتح عملية يعيد محادثتها ونطاقها، ويوقف متابعة العملية السابقة ويصفّر تسلسل الأحداث؛ لا تُطبّق استجابة متابعة قديمة على العملية الجديدة.
- **استعادة الصفحة:** يضاف معرف العملية إلى عنوان الصفحة لتمكين استعادتها بعد إعادة التحميل.
- **الحالات:** انتهاء الرسالة ينتج حالة نهائية أو انتظار قرار المستخدم بحسب الحالة الفعلية. غياب مفتاح النموذج يسجل فشلاً، وليس نجاحاً. إكمال عملية يعيد الوكلاء المشاركين فيها إلى الجاهزية دون إيقاف وكيل يعمل على عملية أخرى.
- **إعادة تشغيل الخادم:** قراءة جميع أحداث العملية، مع اعتماد آخر حالة وحفظ نطاق الشركة والمحادثة. العمليات غير المنتهية التي لا يوجد لها عامل تنفيذي بعد إعادة التشغيل تُسجل كغير محسومة؛ لا يعاد تنفيذها أو اعتمادها تلقائياً.
- **Excel:** معالجة `.xlsx` عبر المحلل والمدقق الحاليين، وحفظ تقرير الصفوف وأسباب الرفض وعرض رابط التقرير. الملفات التالفة أو فشل اتصال Odoo لا ينتج عنها رسالة نجاح. الفحص الجاف ليس استيراداً؛ لا يُكتب أي سجل في Odoo من زر الرفع.
- **الإعدادات:** قراءة بيانات الاتصال الفعلية بدلاً من الشركات الوهمية والنصوص الثابتة. جلب جميع الشركات المتاحة للحساب دون سقف 20 شركة، وتحديث الشركة المختارة في الإعدادات. إضافة نموذج للتحقق من اتصال قاعدة البيانات قبل حفظه، مع حماية المفتاح وعدم إعادته للواجهة.
- **تبديل قاعدة البيانات:** يرفض التبديل أثناء وجود عملية نشطة أو قرار معلق في العملية الحالية. احتفاظ المفتاح السابق متاح فقط عند بقاء الخادم واسم المستخدم نفسيهما؛ لا تعني إضافة الإعدادات منح صلاحيات جديدة لحساب Odoo.
- **الوكلاء:** إضافة الإمكانات وعدد الأحداث والعمليات وآخر الأنشطة الحقيقية وروابط فتح العمليات. أحداث فاحص في حلقة الأدوات تسجل عند تنفيذ القراءة فعلياً، لا لمجرد أن النموذج أجاب عن سؤال.
- **الواجهة:** فقاعات مرسلة ومستقبلة مختلفة المحاذاة والسطح والتسمية؛ شريط كتابة موحد، ونوافذ وسط الشاشة، وتحسين تخطيط الهاتف. مؤشر من ثلاث نقاط يظهر فقط أثناء طلب الرد، ولا يتحرك عند `prefers-reduced-motion`.
- **PDF:** تقرير أبيض A4 للطباعة مع تكرار رأس الجدول والتفاف النص. عند غياب محرّك PDF يرجع خطأ صريح بدلاً من ملف وهمي يبدأ بترويسة PDF فقط.
- **مؤشرات التدقيق:** استبدال نسب ثابتة غير مقاسة ببيانات الملخص أو تسمية واضحة لعدم القياس. تقارير الفحص الجاف لا تُعرض كإثبات استيراد ناجح.

## أساس التصميم والتنفيذ

الواجهة الحالية FastAPI وHTML وJavaScript، وليست React. لذلك تم تكييف نمطي REUI داخل البنية الحالية، وليس تنفيذ أمر shadcn وإضافة مكونات TSX غير قابلة للتشغيل فيها.

- نمط الفقاعات: [REUI c-bubble-1](https://reui.io/r/c-bubble-1.json).
- نمط الترقيم: [REUI c-pagination-15](https://reui.io/r/c-pagination-15.json).

المهارات الموجودة في `.claude/skills` استُخدمت مرجعاً للتصميم. المراجع الإضافية التي طلبها المستخدم استُخدمت لتحسين مراجعة المنفذ فقط، ولم تُضف مهارات أو برومبتات جديدة أو اعتمادات تنفيذية للمشروع.

## التحقق

نجحت مجموعة محددة من 80 اختباراً، بينها 19 اختبار انحدار جديداً. اختبارات Excel الجديدة تشغّل المحلل والمدقق الحقيقيين مع مستودع مراجع Odoo معزول، وليس اتصال إنتاج.

```bash
python -m pytest \
  tests/test_cockpit_repairs.py \
  tests/test_seraj_llm_service.py \
  tests/test_sijil_page_and_export.py \
  tests/test_polling_resilience_and_timeout.py \
  tests/test_sijil_audit_service.py \
  tests/test_dry_run_report.py \
  tests/test_validator.py \
  tests/test_parser.py \
  tests/test_web_service_sijil_laya.py -q
```

تجربة Chromium شملت إرسال طلبين مستقلين، فتح محادثة الطلب الأول من جدول العمليات، البحث عن المعرف، فتح التوثيق، التنقل بين صفحات السجلات، بطاقات الوكلاء، تغيير الشركة باستخدام استجابة اختبارية، ظهور مؤشر الكتابة واختفاءه، تقليل الحركة، وعرض الهاتف بعرض 390px. لم تظهر أخطاء JavaScript في المسارات المجربة، ولم يوجد تجاوز أفقي في تخطيط الهاتف النهائي.

تم توليد PDF حقيقي وفحص أبعاده بأداة `pdfinfo`، والتحقق بصرياً من الخلفية البيضاء. يفصل التحقق بين تحميل الملف وفحصه وبين استيراد موظفين إلى Odoo.

## حدود التحقق

- لم تُختبر الكتابة أو الاستيراد على Odoo حية، ولم يُرسل طلب إلى OpenRouter بمفتاح المستخدم. إعدادات الاتصال ومفتاح النموذج غير مهيأة في بيئة المعاينة.
- اختبارات قديمة تعتمد على اتصال Odoo أو خدمة النموذج فشلت أيضاً عند تشغيلها على نسخة `main` الأصلية قبل هذه التغييرات. لا تمثل نتيجة 80 اختباراً ادعاء بأن كل اختبارات المستودع أو تكاملات الإنتاج قد نجحت.
- الأرشيف القديم قد يحتوي معرفات محادثة مشتركة أو نصوصاً غير محفوظة. لا يمكن إعادة بناء النصوص المفقودة بأمان، ولذلك تعرض الواجهة السجل المتاح دون اختلاق ردود.
- تغيير قاعدة البيانات إعداد عام لخادم التطبيق الحالي، وليس عزلاً مستقلاً لكل مستخدم. يجب تشغيل تحقق تكامل على قاعدة اختبار قبل الدمج أو استخدام التبديل في بيئة متعددة المستخدمين.
- يعتمد التتبع الحالي على خدمة في الذاكرة مع سجل JSONL. لم يُضف نظام مهام موزع أو دعم تشغيل عدة عمال Uvicorn؛ يشغل التطبيق بعامل واحد كما كان.

## التشغيل

```bash
pip install -r requirements.txt
python -m playwright install chromium
# Linux عند الحاجة:
python -m playwright install --with-deps chromium
python -m uvicorn web_service:app --host 127.0.0.1 --port 8000
```

بعد تشغيل النسخة: اختبر اختيار الشركة، وفحص ملف صغير، وفتح تقرير الصفوف، ثم إجراء تعديل تجريبي مع اعتماد بشري والتحقق من الأثر والسجل. لا تضع مفاتيح الإنتاج في المعاينة المؤقتة.

## مراجعة المخاطر

تغييرات تفاصيل التدقيق وحلقة المحادثة مركزية وتؤثر في البحث والتصدير والاعتماد. صنّف تحليل GitNexus المجمع نطاقها عالي الخطورة/حرجاً بسبب مركزية هذه المسارات؛ لذلك لا ينبغي دمجها تلقائياً دون مراجعة الفارق وتشغيل اختبارات التكامل على بيئة اختبار المستخدم.
