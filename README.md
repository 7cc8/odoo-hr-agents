# odoo-hr-agents

> **Phase 1.5 — Runtime المستقر والمحصّن أمنياً (Production-Hardened Hybrid Architecture)**  
> نظام هجين لأتمتة عمليات الموارد البشرية وإدارة الموظفين في Odoo: يجمع بين **مسار حتمي صارم (Deterministic & Fail-Closed Pipeline)** لمعالجة ملفات Excel والكتابة المعتمدة، و**محرك وكلاء ذكي (LLM Agent Runtime)** للاستعلام المباشر والمحادثة والدعم التفاعلي.

---

## 📌 المفهوم المعماري: المساران الأساسيان (Dual-Track Architecture)

يعتمد النظام فصلاً تاماً بين عمليات **التعديل والكتابة** الحساسة، وعمليات **الاستعلام والمحادثة**:

                    ▼                                                                           ▼
      [المسار الأول: المعالجة والكتابة الصارمة]                                   [المسار الثاني: الاستعلام والوكلاء الذكية]
         Strict Deterministic Pipeline                                              LLM-Driven Agent Runtime
                    │                                                                           │
  Excel File Upload (Web / Telegram)                                            User Chat (Dashboard / Telegram)
                    │                                                                           │
  1. Parser & Deterministic Cleaning (cleaning.py)                              1. Seraj (Meta-Agent / Orchestrator)
     - استعادة الصفر للجوال السعودي (05x)                                         - إدارة الحوار وتفكيك الاستعلامات
     - توحيد التواريخ غير الملتبسة (ISO)                                        │
     - إزالة التطويل وتوحيد الكاف والياء                                        2. Shared Agent Runtime (agent_runtime.py)
                    │                                                               - سقف الأدوار (Max Turns = 5)

                    │                                                           │
  3. Dry-Run Inspection Report & Row Hashes                                     3. Fahas (Odoo Inspection & Tools)
                    │                                                               - استعلام مباشر عبر XML-RPC
  4. Explicit HR Approval (approval_schema.py)                                  │
                    │                                                           4. Musleh & Muwaffaq (Repair & Match)
  5. Provenance-Bound Writer (writer.py)                                            - مطابقة ضبابية محسوبة (difflib)

## 🚀 المسار الأول: خط معالجة ملفات Excel الصارم (Strict Pipeline)

جميع ملفات الموظفين تمر عبر خط أنابيب صارم، لا يتدخل فيه أي نموذج ذكاء اصطناعي باتخاذ قرارات القبول أو الكتابة:

1. **المحلل ومرحلة التنظيف الحتمية (`parser.py` + `cleaning.py`):**
   - **الجوال:** معالجة الأرقام العربية/الفارسية، توحيد البادئات الدولية (`+966`)، واستعادة الصفر المفقود تلقائياً (`50xxxxxxx` ← `050xxxxxxx`).
   - **البريد:** تنظيف المسافات والتحويل لأحرف صغيرة (`lower()`).
   - **التاريخ:** تحويل الصيغ الواضحة غير الملتبسة فقط إلى `YYYY-MM-DD`. الحالات الملتبسة (مثل `05-06-2026`) أو التواريخ الهجرية تُترك كما هي ويُبلّغ عنها كـ `cleaning_issues`.
   - **النصوص:** إزالة التطويل (الكشيدة) وتوحيد الحروف الفارسية (`ک` و `ی`).
   - **قالب الموظفين الرسمي:** تخطي صف المثال التوضيحي تلقائياً (`template_example_row_skipped`).
2. **المدقق الصارم (`validator.py`):**
   - مطابقة الشركات والأقسام والمسميات الوظيفية مقابل لقطة Odoo الحية.
   - التحقق من تكرار البريد الإلكتروني في Odoo مع سياسة إغلاق آمنة عند تعذر الاتصال (`Fail-Closed`).
   - تصنيف النتائج إلى: `accepted` (مقبول)، `needs_review` (يحتاج مراجعة)، أو `rejected` (مرفوض).
3. **تقرير الفحص التجريبي (`dry_run_report.py`):**
   - توليد تقرير فحص تفصيلي يحتوي على ملخص الأخطاء، سجل التصحيحات، والتوقيع الفريد لكل صف (`row_hash`).
4. **الموافقة والاعتماد (`approval_schema.py`):**
   - إنشاء ملف اعتماد رسمي مشفر بالتوقيعات لضمان عدم التلاعب بمحتوى الملف بعد الفحص.
5. **الكاتب الموثوق (`writer.py`):**
   - يعيد تحليل الملف من الصفر للتأكد من مطابقة الـ `row_hash` الحية مع التقرير المعتمد.
   - الكتابة المقيدة على سجلات `hr.employee` في Odoo مع التحقق الفوري بعد الإنشاء (`readback`).
   - تسجيل كل عملية في ملف سجلات غير قابل للتعديل (`output/writer_results_*.jsonl`).

> 📖 **تفاصيل معايير الفحص وترتيبها:** راجع وثيقة [دليل الـ Validator وموفق المعتمد](docs/validator_and_matching.md).

## 🤖 المسار الثاني: منظومة الوكلاء ووقت التشغيل (Agent Runtime)

يعمل الوكلاء كفريق متكامل تحت بيئة تشغيل موحدة (`agent_runtime.py`) تضمن استقرار النظام ومنع استنزاف الموارد:

| الوكيل | الدور المعماري | آلية العمل |
|---|---|---|
| **سراج (Seraj)** | المنسق العام ومدير المحادثة | وكيل LLM تفاعلي يدير الحوار ويفوض المهام للوكلاء المتخصصين. |
| **فاحص (Fahas)** | وكيل الاستعلام والفحص في Odoo | يوفر أدوات الاستعلام الآمنة والقراءة فقط من قاعدة بيانات Odoo. |
| **مصلح (Musleh)** | خبير الاستشارات والمعالجة | يقترح حلولاً ورقعاً تصحيحية للصفوف المرفوعة والمرفوضة. |
| **موفق (Muwaffaq)** | مطابق السجلات والكيانات | محرك مطابقة خوارزمي هجين (Exact + Fuzzy difflib + Contextual) بنسب ثقة مركزية. |
| **كاتب (Katib)** | منفذ عمليات Odoo المعتمدة | بوابة تنفيذ محصنة تدعم الإنشاء المعتمد وسيناريوهات التنظيف المعزولة. |
| **سجل (Sijil)** | حارس التدقيق والبيانات | تسجيل شامل وتدقيق لحظي للأحداث والعمليات بصيغة JSONL. |

### خصائص بيئة تشغيل الوكلاء (`agent_runtime.py`):
- **سقف الأدوار:** حد أقصى 5 دورات (`max_turns = 5`) لمنع الحلقات غير المنتهية.
- **مهلة الأدوات:** مهلة حتمية للأدوات (`tool_timeout_s = 60s`) تمنع تجمد المحادثة إذا بطؤ خادم Odoo.
- **بتر النتائج الضخمة:** تحديد أقصى مخرجات للأداة بـ 8000 حرف لتجنب تفجير نافذة سياق النموذج (Context Window).
- **الرصد اللحظي (Observability):** بث أحداث فورية لكل خطوة تفصيلية للمشرف عبر WebSocket ولوحة التحكم.

## 🌐 الواجهات المتاحة للمستخدم

### 1. لوحة التحكم الموحدة (Unified Dashboard)
واجهة ويب متكاملة مبنية بـ FastAPI و Vanilla JS مع ثيم داكن احترافي:
- **مركز رفع الملفات المنفصل (Decoupled Upload Center):** رفع ملفات Excel بالسحب والإفلات، وبدء الـ Dry-run، واستعراض تقارير التصحيح والـ Hashes بشكل مستقل.
- **محادثة الوكيل اللحظية (Live Chat):** محادثة تفاعلية سريعة مع "سراج" للاستعلام عن موظفي Odoo، الأقسام، والإحصائيات.
- **لوحة الأحداث المباشرة (Event Stream):** تتبع لحظي لما يقوم به الوكلاء خطوة بخطوة.

### 2. بوت تيليجرام (Telegram Bot Integration)
- دعم تحميل وتوزيع قوالب الموظفين الرسمية.
- رفع ملفات الإكسل ومعالجتها والحصول على تقارير dry-run مباشرة داخل تيليجرام.

## ⚙️ التشغيل السريع (Quickstart)

### المتطلبات الأساسية
- Python 3.12+
- اتصال بـ Odoo 16 / 17 / 18 (صلاحيات قراءة/إنشاء على `hr.employee`)
- نموذج ذكاء اصطناعي محلي عبر Ollama (`qwen3.5:9b` موصى به) أو مفتاح سحابي.

### 1. إعداد المتغيرات (`.env`)
قم بنسخ ملف `.env.example` إلى `.env` وضبط الإعدادات:
```bash
# Odoo Connection
ODOO_URL=https://your-odoo-instance.com
ODOO_DB=your_db_name
ODOO_USERNAME=your_admin_user
ODOO_API_KEY=your_odoo_api_key

# Web Security & Execution Tokens
AGENT_WRITE_TOKEN=your_secure_write_token

# LLM Configuration (Local Ollama Recommended)
LLM_PROVIDER=ollama
OLLAMA_MODEL=qwen3.5:9b
OLLAMA_BASE_URL=http://localhost:11434

# Or Cloud Providers (Groq / OpenAI / Anthropic)
# GROQ_API_KEY=gsk_...
# OPENAI_API_KEY=sk-...
```

### 2. بدء الخادم وتشغيل واجهة الويب
على أنظمة Windows:
```powershell
# تشغيل خادم الويب الموحد مباشرة
.\start_chat.bat
```
أو عبر السطر البرمجي:
```bash
python web_service.py
# أو
uvicorn web_service:app --host 0.0.0.0 --port 8000 --reload
```
افتح المتصفح على: `http://localhost:8000`

## 🔒 قواعد الأمان وحوكمة البيانات (Security & Guardrails)

1. **الكاتب لا يملك صلاحية الحذف (`Unlink` Is Isolated):** بوابة الكتابة `OdooWriteGateway` لا تحتوي برمجياً على دالة حذف. أدوات التنظيف معزولة تماماً في `OdooCleanupGateway` وتتطلب مفتاح `--confirm` ومطابقة بريد الموظف الحي مع ملف النتائج.
2. **فحص الصلاحيات والبيئة (`Environment Policy`):** منع أي عملية كتابة على بيئات غير مصرح بها.
3. **حماية التكرار المحكمة (`Fail-Closed`):** عند الشك أو تعذر فحص التكرار مع Odoo، يتحول الصف تلقائياً إلى `needs_review` ولا يُقبل بصمت.
4. **تطابق التوقيعات (`Hash Verification`):** لا يمكن كتابة أي صف في Odoo إذا تغير حرف واحد في الملف بين لحظة الفحص التجريبي ولحظة الاعتماد.
